# 新區域與改地圖

改地圖、做新區域、調色、照草稿施工時的做法和工具。給作者自己和協作的 AI 看。

## 區域怎麼組成

一次只建一個區域，用網址的 `?z=` 指定，沒有寫就是畫廊。換區域時整頁重新載入（`location.replace`），上一區的記憶體一定會被收回。

- `js/main.js` 開頭的 `ZONES`：每個區域一行，寫渡海時載入畫面的字，和要載入的 `zone-*.js`。
- `js/zones/gallery/zone-gallery.js`、`js/zones/haishi/zone-haishi.js`：每個區域一個，長一樣，main.js 照順序呼叫：

| 名字 | 什麼時候 | 做什麼 |
|---|---|---|
| `bgm` | — | 背景音樂，`from` 是從哪個房間（或區域）開始放；`src` 是音檔網址，或像畫廊那樣給現場合成的曲子（study.js 的 `StudyNight`） |
| `directorLag` | — | 導演運鏡轉多慢，房間小的區域大一點 |
| `build(scene, { gallery, coarse, params })` | 一開始 | 建場景，回傳 world |
| `env(world)` | 建好之後 | 光線和霧，一組或兩組（兩組的由 `world.outdoor.outdoorness` 漸變） |
| `residents(ctx)` | 角色出來之前 | 選用。固定站著、會擋路的角色 |
| `crowd(ctx)` | 角色出來之後 | 走來走去的：回傳 `{ animals, visitors }` 或 `{ vendors, passers }` |
| `arrive({ player, world, params, ui })` | 載入完 | 站在哪裡、開場鏡頭 |

- `js/core/scenery.js`：每個區域都用得到的零件（`uTime`、`bucketObjects`、`glowPoints`、圖層編號）。新區域從這裡拿，**不要 import `world.js`**，不然會把整個畫廊一起載進來。

## 新增一個區域

1. `main.js` 的 `ZONES` 加一行。
2. 照 `zone-haishi.js` 寫一個 `zone-<名字>.js`。
3. `index.html` 開頭「從別的區域搭船過來」那段，把渡海的字加上去（跟 `ZONES` 一樣）。
4. 上傳時 `tools/stamp.ps1` 會自己順著 import 找出這一區要先下載的模組，不用手寫清單。它會提醒沒有被用到的 js。

## 歸門：地圖最深處回畫廊的法陣

每張地圖最深處放一個，`js/scene/homedoor.js` 的 `buildHomeCircle({ x, y, z, R, obstacles, exits })`：地上刻六芒星、六盞火盆，點齊了畫廊的前門從半空蹦出來，推開走進去就回前廳（`travel(..., true)`，到了是 `?from=door`）。

- 法陣中心到四周至少要 4 公尺平地；門朝北（-z），門口在中心往北一公尺，北邊兩盞火盆中間要能走過去。
- `exits` 傳 zone 回傳的那個陣列：門立著的時候它自己把門口放進去、收掉時拿出來。zone 回傳 `home`，main.js 會接好多人同步（multiplayer.js 的 `gate`）、聲音、每幀更新。
- 法陣照當地文化做（石台、火盆的樣子），門永遠是 frontdoor.js 的 `doorParts`。角色現在只會畫六芒星，別的種族的法陣以後加在 `SHAPES`。
- 海市的在半山亭東邊（AREAS 的 `reditus`）。這塊後來才接上，所以欄杆照「沒有它的時候」圍，接口那一截蓋進丟掉的零件，亂數照抽。

## 亂數：每個區塊各用一組

海市是一條亂數序列從頭抽到尾，前面多抽一次，後面整排房子就換樣子，所以改地圖要靠「added 排最後」和 `SEEK` 對齊。這套做法在海市維持原樣，不改。

新區域從第一天就讓每個區塊各自用一組亂數，種子用區域名和區塊 id：

```js
const R = rng(`${zone}:${area.id}`);          // 這個區塊的房子、燈籠、雜物都從這裡抽
const RL = rng(`${zone}:${area.id}:lanterns`); // 同一塊裡不同的東西也可以分開
```

這樣改 A 區不會動到 B 區；新增區塊也不必排在最後。

**不要合併各檔案裡的 `hash`、`rng`、`smooth`。** 它們算法不同，換掉任何一個，用它擺放的東西全部會移位。

## 工具

都只在自己電腦上用，不會上傳，不影響線上。

| 做什麼 | 怎麼用 |
|---|---|
| 平面圖（畫草稿用） | `node tools/haishi-plan.mjs` → `tools/out/haishi-plan.svg`。北在上、海在下，每公尺一條細線、每 5 公尺標座標；淺色是走得到的區塊（id 和高度），深色是房子和牆，紅線是欄杆，圓點是攤位。草稿直接畫在這張圖上，位置就對得上程式的 x、z |
| 路網檢查 | `node tools/check-haishi.mjs`：斷層、走不到、沒有欄杆的邊 |
| 路人檢查 | `node tools/check-crowd.mjs` |
| 疊參考圖 | 網址加 `?ref=originals/草稿.png`（`originals/` 不會上傳），或開了 `?ref` 之後把圖拖進畫面。左下角調透明度、拉分割線左右對照 |
| 站到某個位置看 | 海市：`?z=haishi&view=x,z,面向(度),鏡頭距離,俯角(度)` |
| 調色 | `?debug`：調色台（預設在右上，可以拖著走、拉大小，` 鍵收起來），分區、色調庫、曲線、顏色、霧、這一區的霧和煙、光線、參考圖都在裡面。拉了馬上看到，「複製」把整段 `export const grade` 貼回 zone 檔。做法見下面「調色」 |
| 效能 | `?debug` 左上角：幀率、draw call、三角形數 |

調色時以桌面插圖 23 為準：網址加 `?debug&ref=originals/插圖.png`，參考圖的控制也在調色台裡。

## 調色

調色寫在 zone 檔的 `export const grade = {...}`（grade.js 讀它）。一張地圖可以分區調：

```js
export const grade = {
  density: 0.016, falloff: 0.04, base: -0.6, start: 6, maxFog: 1,      // 全區
  exposure: 0, contrast: 1.6, shadow: '#16151b', gain: '#ffffff', ...,
  tune: { 霧Color: '#66708e' },                                        // 這一區登記的霧和煙
  regions: [
    { name: '碼頭', at: [0, 20], r: 10, fade: 6, contrast: 1.3 },          // 圓：中心、半徑、往外漸變幾公尺
    { name: '星廟', box: [-30, -70, -10, -50], fade: 8, tone: '海市藍夜', exposure: -0.3 },  // 方框
  ],
};
```

- 分區只寫跟全區不一樣的幾項；照順序疊上去，後面的蓋前面的。角色（攝影模式是鏡頭）走過漸變那一段時慢慢換過去。
- `tone: '名字'` 套用 js/core/tones.js 裡存好的色調，後面再寫要另外改的。新地圖可以直接寫 `grade = { tone: '海市藍夜' }` 起步。
- 霧有兩層：高度霧（density 到 maxFog）貼著地面和海面，最多蓋到 maxFog；遠景空氣（`far`、`farAir`）不看高低，`far` 公尺以外越遠越接近 `farAir`，收向天邊的顏色（霧色 × 天空球的「天邊深淺」）。只有高度霧又把 maxFog 調低的話，過了某個距離每樣東西都一樣灰、遠山跟天接的地方一刀切開，這時開遠景空氣。`far: 0` 是沒有。
- 自己寫的海面這種要自己霧色的，`gradeSurface(col, 高度霧, 霧色, 遠景空氣)` 四個參數分開傳，見 haishi-sky.js 的海面。
- 光線（天光、主光、霧色）整個區域一組，不分區：霧色同時是天空接地平線的顏色，分區換霧色會在地平線多一條線。要讓一塊比較暗，用分區的「物件曝光」。

調色台的用法：

- 位置：抓標題列拖到別處，靠近畫面邊緣會貼齊（貼右邊的會跟著視窗寬度走）；下面兩角拉寬高、左右兩邊拉寬，曲線框跟著變大；標題列按兩下回到右上角。位置記在這台電腦。
- 「分區」：＋圓／＋方框在角色站的地方加一塊，地上會畫出範圍（橘的是正在改的那塊）。勾「跟著位置」走進哪塊就改哪塊；勾「只看這組」不管站在哪都只看正在改的那組。
- 數值：名字左右拖曳微調（Shift 細、Alt 粗），按兩下還原；格子可以直接打數字。分區裡橘色的名字是這塊自己改的，按兩下就回到跟全區一樣。全區裡有藍點的是跟 zone 檔不一樣的。
- 曲線：底下灰色的是現在畫面的明暗分布。選了點以後方向鍵微調、Delete 刪掉。
- 按住 B 看調色前、按住 N 看 zone 檔原本的版本；Ctrl+Z／Ctrl+Y 復原、重做。
- 還沒貼回 zone 檔的改動會留一份草稿在這台電腦，重新整理後工具列會問要不要載入。
- 「色調庫 → 存成色調」先存在這台電腦，同時複製一行，貼進 js/core/tones.js 才會上線。

效能：調色在每個像素都做，但霧色、支點這些整個畫面都一樣的先在 CPU 算好；四條曲線都是直的就不查表；分區只有走過邊界時才重新混一次，平常每幀幾乎不花時間。分區多不會讓畫面變慢，花時間的是畫面上疊了幾層霧和光暈。
