# 新區域與改地圖

改地圖、做新區域、調色、照草稿施工時的做法和工具。給作者自己和協作的 AI 看。

## 區域怎麼組成

一次只建一個區域，用網址的 `?z=` 指定，沒有寫就是畫廊。換區域時整頁重新載入（`location.replace`），上一區的記憶體一定會被收回。

- `js/main.js` 開頭的 `ZONES`：每個區域一行，寫渡海時載入畫面的字，和要載入的 `zone-*.js`。
- `js/zones/gallery/zone-gallery.js`、`js/zones/haishi/zone-haishi.js`：每個區域一個，長一樣，main.js 照順序呼叫：

| 名字 | 什麼時候 | 做什麼 |
|---|---|---|
| `bgm` | — | 背景音樂，`from` 是從哪個房間（或區域）開始放；`src` 是音檔網址，或像畫廊那樣給現場合成的曲子（study.js 的 `StudyNight`） |
| `directorLag` | — | 導演運鏡轉多慢，房間小的區域大一點 |
| `build(scene, { gallery, coarse, params })` | 一開始 | 建場景，回傳 world |
| `env(world)` | 建好之後 | 光線和霧，一組或兩組（兩組的由 `world.outdoor.outdoorness` 漸變） |
| `residents(ctx)` | 角色出來之前 | 選用。固定站著、會擋路的角色 |
| `crowd(ctx)` | 角色出來之後 | 走來走去的：`{ animals, visitors, vendors, walkers }`。前三種主程式認得（擋路、座位、互動鍵）；`walkers` 是一個陣列，放其他只是走來走去的人（海市的路人、汀站的旅客、靜海的海牛人和旅客），每個要有 `update(dt, player)`，可以有 `lookables(push)`（注意力）和 `hidden`（照相館拍照時藏起來）。新區域的住民寫成這樣就接得上，不用改 main.js |
| `arrive({ player, world, params, ui })` | 載入完 | 站在哪裡、開場鏡頭。`?view=x,z,面向,距離,俯角` 由 main.js 在 arrive 之後統一處理，zone 檔不用寫 |
| `beast` | — | 選用。白獸（`js/npc/beast.js`）可能出現的地方：`{ spots: [{ x, z, place, room }] }`，八到十五個；`place` 是登報的地名，`room` 是畫廊第幾間（那間藏起來時牠也藏）。每個點周圍 0.7 公尺要走得到、地面平，前面三公尺半要能跳出去；`?debug` 時太擠的會在主控台提醒。沒寫的區域從 `spawn`、出口、攤位附近自己挑十個 |

- `js/core/scenery.js`：每個區域都用得到的零件（`uTime`、`bucketObjects`、`glowPoints`、圖層編號）。新區域從這裡拿，**不要 import `world.js`**，不然會把整個畫廊一起載進來。

## 住民、路人

走來走去的人有三層，新區域從底下往上拿：

- `js/npc/crowdkit.js`：底座。`CharacterPool`（近處用完整的角色，固定幾個輪著用，一幀最多換一個人的外觀）、`FarFigures`（遠處兩個簡單形狀一次畫完）、`dodgeFrom`／`easeOffset`（玩家靠近往旁邊讓）、`turnHead`、`ghostStep`、`hash`、`wrap`。
- `js/npc/cast.js`：選角。`personLook(R, 本地人?, 左手, 出沒的地方)` 抽一套合法的外觀（本地人四種、外地人），`FACE` 五官表。區域自己的衣櫃（汀站旅客）寫在自己的檔，只借 FACE。
- 時間表：照「現在幾點」算在哪，大家看到的一樣。三種寫法照需要挑：海市路人照雜湊排行程（passersby.js 的 Roads、makeTrip），汀站旅客照時刻表（ting-travelers.js），海牛人和靜海旅客走固定路線（`js/npc/timeline.js` 的 `timeline(nodes)`、`at(tl, t, out)`，一串點加停的秒數，第一幀就在半路上）。
- 台詞不跟邏輯混：放 `*-lines.js`（訪客 npc/visitor-lines.js、攤販 npc/vendor-lines.js、胖頭 npc/manatee-lines.js、樹洞 zones/gallery/hollow-lines.js），改完 `node tools/lines.mjs` 重新整理 docs/NPC台詞整理.md；新的台詞檔在 lines.mjs 的 SOURCES 登記一筆。

整理路人程式時 `node tools/smoke.mjs --diff base` 另外比「路人指紋」（海市、汀：時鐘釘在同一刻，每個人該在哪、長什麼樣）。

## 新增一個區域

1. `main.js` 的 `ZONES` 加一行。
2. 照 `zone-haishi.js` 寫一個 `zone-<名字>.js`。
3. `index.html` 開頭「從別的區域搭船過來」那段，把渡海的字加上去（跟 `ZONES` 一樣）。
4. 上傳時 `tools/stamp.ps1` 會自己順著 import 找出這一區要先下載的模組，不用手寫清單。它會提醒沒有被用到的 js。

## 歸門：地圖最深處回畫廊的法陣

每張地圖最深處放一個，`js/scene/homedoor.js` 的 `buildHomeCircle({ x, y, z, R, obstacles, exits })`：地上刻六芒星、六盞火盆，點齊了畫廊的前門從半空蹦出來，推開走進去就回前廳（`travel(..., true)`，到了是 `?from=door`）。

- 法陣中心到四周至少要 4 公尺平地；門朝北（-z），門口在中心往北一公尺，北邊兩盞火盆中間要能走過去。
- `exits` 傳 zone 回傳的那個陣列：門立著的時候它自己把門口放進去、收掉時拿出來。zone 回傳 `home`，main.js 會接好多人同步（multiplayer.js 的 `gate`）、聲音、每幀更新。
- 法陣照當地文化做（石台、火盆的樣子），門永遠是 frontdoor.js 的 `doorParts`。角色現在只會畫六芒星，別的種族的法陣以後加在 `SHAPES`。
- 海市的在半山亭東邊（AREAS 的 `reditus`）。這塊後來才接上，所以欄杆照「沒有它的時候」圍，接口那一截蓋進丟掉的零件，亂數照抽。

## 星門：不搭船，從一道門走到另一區

海市星廟無像殿最裡面那道星門通到鏡宮（`?z=jinggong`），鏡宮門口回到星門前。

- 出口寫 `{ x, z, r, to, gate: true, title, label }`。main.js 的 onExit 看到 `gate` 就 `travel(to, {}, 'gate')`：門光鋪滿就換頁，網址帶 `from=<這一區>&via=door`，到的那頁一開始就是門光（index.html 開頭那段），不渡海。
- 到的那一區在 `arrive` 照 `from` 決定站哪。海市從鏡宮回來站在星門前（world 的 `templeGate`，haishi-temple.js 的 buildStarGate 算的）。
- 這種區域不放進 `scene/places.js`：不在渡船卡、樹洞的航路上。

## 鏡宮

- 平面圖在 `js/zones/jinggong/jinggong-map.js`：三角格子上的多邊形，`ADD` 的聯集扣掉 `CUT`（鏡柱），邊要沿格線（0°、60°、120°）。牆全是鏡子；`PANELS` 是地面中間的雙面鏡板，`DOORS` 是邊界上不是鏡子的一段。燈、地名、白獸的點也在這個檔。
- 反射在 `jinggong-mirror.js`：每一幀從鏡頭追光束，`TUNE` 的 pieces（一幀追幾塊）、depth（反射幾次）、far（多遠）決定看多深。人的倒影是場景裡所有 `userData.character` 的角色，本人照常畫，倒影用同一組燈。
- 改完先開 `experiments/mirror_preview.html` 看，左上角有幀率、光束數、燈數、倒影數，開關可以一項一項關掉比較。
- 天花板只有 3.2 公尺：zone 回傳 `camLift: 0`（player.js），鏡頭撞到牆或天花板就往前移，不往上抬。

## 亂數：每個區塊各用一組

海市是一條亂數序列從頭抽到尾，前面多抽一次，後面整排房子就換樣子，所以改地圖要靠「added 排最後」和 `SEEK` 對齊。這套做法在海市維持原樣，不改。

新區域從第一天就讓每個區塊各自用一組亂數，種子用區域名和區塊 id：

```js
const R = rng(`${zone}:${area.id}`);          // 這個區塊的房子、燈籠、雜物都從這裡抽
const RL = rng(`${zone}:${area.id}:lanterns`); // 同一塊裡不同的東西也可以分開
```

這樣改 A 區不會動到 B 區；新增區塊也不必排在最後。

**不要合併各檔案裡的 `hash`、`rng`、`smooth`。** 它們算法不同，換掉任何一個，用它擺放的東西全部會移位。

## 調色

調色寫在 zone 檔的 `export const grade = {...}`（grade.js 讀它）。一張地圖可以分區調：

```js
export const grade = {
  density: 0.016, falloff: 0.04, base: -0.6, start: 6, maxFog: 1,      // 全區
  exposure: 0, contrast: 1.6, shadow: '#16151b', gain: '#ffffff', ...,
  tune: { 霧Color: '#66708e' },                                        // 這一區登記的霧和煙
  regions: [
    { name: '碼頭', at: [0, 20], r: 10, fade: 6, contrast: 1.3 },          // 圓：中心、半徑、往外漸變幾公尺
    { name: '星廟', box: [-30, -70, -10, -50], fade: 8, tone: '海市藍夜', exposure: -0.3 },  // 方框
  ],
};
```

- 分區只寫跟全區不一樣的幾項；照順序疊上去，後面的蓋前面的。角色（攝影模式是鏡頭）走過漸變那一段時慢慢換過去。
- `tone: '名字'` 套用 js/core/tones.js 裡存好的色調，後面再寫要另外改的。新地圖可以直接寫 `grade = { tone: '海市藍夜' }` 起步。
- 不要高度霧、只調顏色的區域寫 `linear: 1`，霧照 env 的線性霧（near、far）：畫廊、月球、汀都是，例如 `grade = { linear: 1, tone: '畫廊01' }`。
- 霧有兩層：高度霧（density 到 maxFog）貼著地面和海面，最多蓋到 maxFog；遠景空氣（`far`、`farAir`）不看高低，`far` 公尺以外越遠越接近 `farAir`，收向天邊的顏色（霧色 × 天空球的「天邊深淺」）。只有高度霧又把 maxFog 調低的話，過了某個距離每樣東西都一樣灰、遠山跟天接的地方一刀切開，這時開遠景空氣。`far: 0` 是沒有。
- 自己寫的海面這種要自己霧色的，`gradeSurface(col, 高度霧, 霧色, 遠景空氣)` 四個參數分開傳，見 haishi-sky.js 的海面。
- 沙塵這種空氣另外兩樣，預設是 0（沒有）：`drift` 霧團（高度霧的濃淡照一張被風吹著走的雜訊圖變，`driftSize` 是團多大；風往哪吹由區域每一幀加 `GRADE.driftOff`）、`scatter` 朝陽發亮（看向太陽時霧和天邊被照亮，`scatterPow` 越大越集中在太陽附近，`scatterColor` 是顏色；太陽的方向由區域寫 `GRADE.sunDir`，長度是太陽多亮）。天空球要跟霧接得起來，就在天空的著色器裡加同一個 `gradeScatter`（見 shenlou.js 的天空球）。
- 對比 1、飽和 1、亮處鮮豔 0 時，著色器走快的那條（`plain`）：霧和遠景空氣在線性色裡一次混完，少換兩次色彩空間。蜃樓為了手機刻意維持這三個值；要拉對比時記得這一條會關掉。
- 光線（天光、主光、霧色）整個區域一組，不分區：霧色同時是天空接地平線的顏色，分區換霧色會在地平線多一條線。要讓一塊比較暗，用分區的「物件曝光」。
- 天氣也是分區：`{ name: '雨後', weather: 'wet', tone: '海市雨後' }`、`{ name: '雨', weather: 'rain', tone: '海市雨夜' }` 沒有範圍，權重是現在的天氣（grade.js 的 WEATHER，海市的 rain.js 每一幀寫）。天氣的分區疊在前一個天氣分區上，「雨」只寫比「雨後」多的。下雨的時間表在 js/core/weather.js（照伺服器時間，大家同一場），雨絲、遮雨圖、燈光圖在 js/zones/haishi/rain.js，濕的地面在 js/core/wet.js。新區域要下雨：weather.js 的 CLIMATES 加一行，再照 rain.js 接；雨絲、沙粒這種粒子共用 js/core/weatherfx.js（`quadStreaks` 幾何、跟著鏡頭的盒子 `driftStep`、寬度照螢幕 `fitScreen`、畫質 `qualityOf`），第三種天氣直接拿來組。`?debug` 時的把手（`__rain`、`__dust` 的 force／next／soon）都在 weather.js 的類別上。
- 塵也是天氣（蜃樓）：`{ name: '沙停', weather: 'calm', tone: '沙島沙停' }`、`{ name: '風沙', weather: 'dust', tone: '沙島風沙' }`，全區本身就是平常的濃塵。時間表是 weather.js 的 Dust（十二分鐘一格：平常、起風沙、沙停），霧色和光線怎麼跟著變、地上的流沙、沙粒在 js/zones/shenlou/shenlou-dust.js，風聲在 shenlou-wind.js。「風沙」疊在「沙停」上，兩組要寫一樣的幾項。

調色台的用法：

- 位置：抓標題列拖到別處，靠近畫面邊緣會貼齊（貼右邊的會跟著視窗寬度走）；下面兩角拉寬高、左右兩邊拉寬，曲線框跟著變大；標題列按兩下回到右上角。位置記在這台電腦。
- 「分區」：＋圓／＋方框在角色站的地方加一塊，地上會畫出範圍（橘的是正在改的那塊）。勾「跟著位置」走進哪塊就改哪塊；勾「只看這組」不管站在哪都只看正在改的那組。
- 數值：名字左右拖曳微調（Shift 細、Alt 粗），按兩下還原；格子可以直接打數字。分區裡橘色的名字是這塊自己改的，按兩下就回到跟全區一樣。全區裡有藍點的是跟 zone 檔不一樣的。
- 曲線：底下灰色的是現在畫面的明暗分布。選了點以後方向鍵微調、Delete 刪掉。
- 按住 B 看調色前、按住 N 看 zone 檔原本的版本；Ctrl+Z／Ctrl+Y 復原、重做。
- 還沒貼回 zone 檔的改動會留一份草稿在這台電腦，重新整理後工具列會問要不要載入。
- 「色調庫 → 存成色調」先存在這台電腦，同時複製一行，貼進 js/core/tones.js 才會上線。
- 調雨天：「分區」底下的「天氣」一排先把天氣固定（毛毛雨、大雨、雨後、乾），點「雨」或「雨後」那一組來改；雨絲、濕地、燈影、光暈的參數在「這一區的霧、煙、海、天」最後幾格。「看起雨」「看收雨」跳到快下、快停的時候看整段轉換。

效能：調色在每個像素都做，但霧色、支點這些整個畫面都一樣的先在 CPU 算好；四條曲線都是直的就不查表；分區只有走過邊界時才重新混一次，平常每幀幾乎不花時間。分區多不會讓畫面變慢，花時間的是畫面上疊了幾層霧和光暈。
